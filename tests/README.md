# مجلد الاختبارات — لا كتالوج، مفردات واحدة

القوالب القديمة الـ28 **حُذفت** (الأولوية 10). ما بقي ليس كتالوجاً أصغر، بل **مفردات**: كل خزانة في الاختبارات تُبنى من
الحقول التي تكتبها لوحة التحكم نفسها — فئة، ثلاثة مقاسات، أقسام، طريقة فتح، واجهة، فاصل، قاعدة.

```
tests/
├── product/       ← المنتج + المحرّكات (219 اختباراً)
├── compat/        ← وعود المحرّكات على كامل المفردات (39 اختباراً: رسم = قائمة قص، مقاسات، عتاد، fuzz)
├── fixtures/
│   └── matrix.ts  ← لوحة التحكم كبيانات: 34 تكويناً مسمّى (washerBay · blindBase · ovenColumn …)
├── taxonomy.test.ts ← الحارس: لا كتالوج يعود، ولا اختبار يُسمّي قالباً متقاعداً
└── README.md
```

## كيف تُشغَّل

| الأمر | ماذا يشغّل |
|---|---|
| `npm test` | الكل: product + compat + الحارس |
| `npm run test:product` | المنتج فقط — **هذا هو بوابة الإصدار** |
| `npm run test:compat` | وعود المحرّكات على المفردات |
| `npm run test:ui` | واجهة React (Vitest + jsdom) |
| `npm run typecheck:tests` | فحص نوعي للمجلدين |

## القاعدة (يفرضها `taxonomy.test.ts`)

| المجموعة | مسموح لها | ممنوع عليها |
|---|---|---|
| `fixtures/matrix.ts` | كتابة **قيم حقول** فقط | تسمية قالب متقاعد (`config('Washer_Bay')`) |
| `product/` | استعمال `M.config('key')` أو `M.MATRIX` | استيراد كتالوج محذوف |
| `compat/` | مسح `MATRIX` كاملاً أو توليد مسودات عشوائية منه | أن تكون منتجاً متنكّراً: يجب أن تمسح المفردات فعلاً |
| `tests/` (الجذر) | `taxonomy.test.ts` فقط | أي ملف اختبار آخر |

**الاستثناء الوحيد:** `templates4` يمرّر `subtype: 'Washer_Bay'` كنصّ إلى `cabinetToDraft` — لأن ما يختبره هو أن
**مشروعاً محفوظاً** بقالب قديم ما زال يُفتح ويُحوَّل إلى `Standard_Base`. هذا ليس إدخالاً للقالب، بل اختبار توافق.

## ماذا يغطّي كل ملف

### product/ — ما نسلّمه
| الملف | يحمي |
|---|---|
| `engines` | **السعر = مجموع صفوف BOM**، و**الرسم = BOM** (الوعدان الأساسيان) |
| `rules` | الحركات، الفتح، أدراج، إطار السحب، مفصلات، فواصل |
| `base` | الأرجل، الوزرة، القاعدة الخشبية، `APPLIANCE_BAY` |
| `bayUnderZone` | الجهاز الأرضي يحكم البدن (بلا لوح قاع/ظهر) |
| `structure` | صناديق L/Z، عدم تداخل الأبواب |
| `lCorner`, `kitchenLayout` | زوايا L، حدود الجدران، `OUT_OF_BOUNDS` |
| `templates4` | نقاط البداية الأربع + حدود الأبعاد |
| `columns` | تقسيم الأعمدة (عمود الجهاز، الرفوف) |
| `gola-trim`, `applianceSize` | قنوات Gola، أحجام الأجهزة |
| `stockShortage`, `stockLedger` | نقص المخزون ودفتر الحجز الكامل |
| `regressions` | مخزون الوهم، تقريب الفاتورة، الأقسام المتدهورة |
| `accessories`, `modelLibrary`, `onlineSources`, `materials` | المكتبة، النماذج الخارجية، الذاكرة، تحرير الموارد |

### compat/ — وعود المحرّكات على المفردات
| الملف | يحمي |
|---|---|
| `audit` | مسطرة التدقيق: لا إنذار كاذب على أي تكوين |
| `dimensions` | سلسلة المقاسات تُطابق الارتفاع، والخطوط بطول قيمها |
| `fasteners` | الكامات والمفصلات والمثبتات = BOM، ولا تعارض بعد التفكيك |
| `applianceBay` | تجويف الجهاز الأرضي: جانبان وعارضتان، بلا قاع ولا ظهر |
| `blindCorner` | العمود الفاصل: باب على الجزء الظاهر ولوح ثابت على الأعمى |
| `fuzz` | 1500 خزانة عشوائية تُبنى من المفردات نفسها |

## لماذا `matrix.ts` وليس `corpus.ts`؟

`corpus` كان اسماً محايداً حول كتالوج قديم. `matrix` لا يلتفّ حول شيء: يكتب **ما تكتبه الاستمارة**.
النتيجة المقيسة: 34 تكويناً تغطّي 9 قدرات لا يصل إليها أي قالب (تجويف جهاز · `OPEN` · `APRON` · عمود فاصل · `PUSH` ·
زجاج · إطار سحب · طوابق متعددة · قاعدة خشبية)، وبلا صيانة 28 تسمية عربية وملاحظة.
