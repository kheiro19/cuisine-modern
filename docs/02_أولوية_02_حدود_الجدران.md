## 1. المشكلة قبل الإصلاح

`nextFreeX` كانت تُرجع دائماً رقماً — حتى لو كان خارج الجدار:

```ts
export function nextFreeX(cabinets, run, category, widthMm, fromMm = 0): number {
  …
  return x;           // ← لا فحص لـ x + widthMm <= wallLength
}
```

و`fitStates` لم تكن تعرف إلا حالتين: `OVERLAP` و`TOUCHING`. النتيجة:

- إضافة خزانة على جدار ممتلئ ⇒ تُوضع خارج نهاية الجدار **بصمت**.
- سحب/كتابة موضع يدوياً ⇒ لا شيء يمنع تجاوز النهاية.
- «ترتيب تلقائي» ⇒ يرصّ الوحدات خارج الجدار بلا اعتراض.
- الجدران الجانبية B و C لم يكن لها **طول معروف أصلاً** (النوع `KitchenLayout` لا يحتوي إلا على `widthMm`).

## 2. الحل

### أ. نوع التخطيط صار يعرف عمق الغرفة

```ts
export interface KitchenLayout {
  type: LayoutType;
  widthMm: number;              // طول الجدار الخلفي A
  depthMm?: number;             // ← جديد: طول الجدارين B و C (اختياري، افتراضي 2400)
  lSide: 'LEFT' | 'RIGHT';
}

export function wallLengthOf(layout: KitchenLayout, run: RunId): number {
  return run === 'A' ? layout.widthMm : layout.depthMm ?? DEFAULT_ROOM_DEPTH_MM;
}
```

### ب. ثلاث دوال جديدة

| الدالة | الدور |
|---|---|
| `offWallMm(cab, layout)` | كم مليمتراً تتجاوز الوحدة نهاية جدارها (0 إن كانت داخله) |
| `clampOnWall(x, width, wall)` | موضع مضمون داخل الجدار — تُستخدم في السحب والكتابة اليدوية |
| `placeAlongWall(...)` | موضع الإضافة أو **سبب الرفض**: `TOO_WIDE` / `WALL_FULL` مع `freeMm` |

### ج. حالة خامسة في `fitStates`

```ts
export type FitState = 'OVERLAP' | 'OUT_OF_BOUNDS' | 'TOUCHING' | 'FREE';
```

الأولوية: `OUT_OF_BOUNDS` > `OVERLAP` > `TOUCHING` > `FREE`
(البقاء خارج الجدار أسوأ من التداخل: التصميم غير قابل للتنفيذ أصلاً.)

### د. ربط الواجهة

| المسار | قبل | بعد |
|---|---|---|
| زر الإضافة | يضيف دائماً | يرفض بسبب واضح: «المتبقي 300 مم والمطلوب 600 مم» |
| الأسهم ← → | `Math.max(0, x)` فقط | `clampOnWall` — لا تجاوز للنهاية |
| كتابة X يدوياً | تُقبل كما هي | تُقصّ إلى داخل الجدار |
| نقل إلى جدار آخر | يضع دائماً | يرفض إن لم يكن هناك مكان |
| ترتيب تلقائي | يرصّ خارج الجدار | لا يُحرّك شيئاً ويشرح لماذا |
| مؤشر الوحدة | أحمر = تداخل | أحمر غامق + لافتة 🚧 «خارج الجدار» |
| لوحة «شكل المطبخ» | طول الجدار فقط | + **عمق الغرفة** (طول الجدار الجانبي) |

## 3. الاختبارات الأربعة الجديدة (أحمر → أخضر)

| الاختبار | يحمي من |
|---|---|
| `walls: the back wall is the room width, a side wall is the room depth` | اختلاط طول الجدار الخلفي بالجانبي |
| `bounds: … OUT_OF_BOUNDS, on every wall` | الخروج من A و B و C، والمواضع السالبة، وسماحية 0.5 مم |
| `placement: … REFUSED, never silently placed past the end` | `WALL_FULL` · `TOO_WIDE` · استعمال فراغ كافٍ · رفض بقايا صغيرة |
| `moving: … clamped inside its wall` | السحب والكتابة اليدوية |


## 4. التحقق الحيّ (تشغيل فعلي)

```
wall A = 3000 mm · wall B = 2400 mm
جدار ممتلئ 3000/3000 + إضافة 600 → {"ok":false,"reason":"WALL_FULL","wallMm":3000,"freeMm":0}
خزانة 3200 على جدار 3000      → {"ok":false,"reason":"TOO_WIDE","wallMm":3000,"freeMm":3000}
سحب إلى 2600 (عرض 600)        → 2400
وحدة عند 2500..3100           → state = OUT_OF_BOUNDS · تجاوز = 100 mm
جدار جانبي B: 1800..2400      → FREE
جدار جانبي B: 1900..2500      → OUT_OF_BOUNDS
```
