## 1. ما كان الوضع عليه

```
grep -r "@ts-nocheck"  →  24 ملفاً (كل الاختبارات + fixtures/legacy)
```

كل الاختبارات كانت **خارج أي فحص نوعي**: خطأ في اسم دالة، أو في عدد الوسائط، أو في حقل غير موجود — لا يظهر إلا عند التشغيل (إن ظهر أصلاً).

الادّعاء في `docs/00` كان: «`tsc` على `src` = صفر أخطاء، والاختبارات غير مشمولة في `tsconfig` أصلاً» — صحيح، ولكن **غير المشمول لا يعني سليماً**.

## 2. البنية الجديدة

| الملف | يفحص | الإعدادات |
|---|---|---|
| `tsconfig.json` (قائم) | `src` | strict كما هو — يبقى فحص البناء |
| **`tsconfig.tests.json`** (جديد) | `tests/` (22 ملف) | `target/lib: ES2022` (لأن الاختبارات تستعمل `.at()`)، `strictNullChecks: false` |
| **`tsconfig.ui.json`** (جديد) | `ui-tests/` | **strict كما في `src`** (لأنه يستورد `App.tsx`) |

```
npm run typecheck         → tsc على src
npm run typecheck:tests   → tsc على tests + ui-tests
```

### لماذا `strictNullChecks: false` في الاختبارات فقط؟

جرّبت الوضع الصارم أولاً: **584 خطأ**، معظمها `'x' is possibly undefined` في تجهيزات (`fixtures`) تكتب أرقاماً صريحة. إصلاحها كله يعني ~300 علامة `!` تُضعف القراءة بلا فائدة حقيقية.
الوضع الحالي يكشف ما يهم فعلاً: **الاسم الخاطئ، الوسيطة الناقصة، الحقل غير الموجود، الوحدة الخاطئة** — وهذا ما أثبته الجدول أدناه.
⚠️ الاستثناء: رمز الواجهة `ui-tests` يُفحص **صارماً** لأن `App.tsx` يعتمد على تضييق الاتحادات (discriminated unions) الذي يتعطّل بدون `strictNullChecks`.

## 4. ما اكتشفه الفحص فعلاً (لا مجرد «تجميل أنواع»)

### 4.1 اختبار كان يقارن السعر بنفسه — `lCorner.test.ts:93`

```ts
// قبل
assert.equal(r2(computeCabinetTotalCost(cab, …)), r2(pr.totalDA ?? pr.total ?? computeCabinetTotalCost(cab, …)));
```

`CabinetPricing` **لا يملك** حقلاً اسمه `total` (اسمه `totalDA`). عند غياب `totalDA` كان السطر يقارن القيمة بنفسها ⇒ **ينجح دائماً**.

```ts
// بعد
assert.equal(r2(computeCabinetTotalCost(cab, …)), r2(pr.totalDA), 'priced');
```

### 4.2 تقرير BOM يدوي ناقص الحقول — `regressions.test.ts:186`

كان الاختبار يبني `FinalBOMReport` يدوياً بلا `shortages`/`stockLedger` (الحقلان اللذان أُضيفا في الأولويتين 4 و6). TypeScript منعه فوراً:
أُضيف `shortages: []` و`stockLedger: []`.

### 4.3 قراءة حقل من فرع الفشل دوماً — `accessories.test.ts`

```ts
assert.ok(r.ok, `${cid}: ${r.error}`);   // r.error يُقرأ حتى عند النجاح
```
`PlaceResult` اتحاد: `{ok:true, placed}` أو `{ok:false, error}`. الرسالة تُبنى **قبل** الفحص ⇒ قراءة حقل غير موجود.
أُضيف مساعدان `okPlace` / `okNudge` يرميان عند الفشل ويُعيدان النوع الناجح.

### 4.4 وسيطة رابعة «إجبارية» في مساعد اختبار

```ts
function addAll(ids, cabs = RUN, scene = SCENE, host) { … }   // host بلا افتراضي ⇒ 4 وسائط إلزامية
addAll(['sink-single']);                                      // 1 وسيطة
```
كان يعمل وقت التشغيل (`undefined`)، وTS كشفه كعقد مكسور.

### 4.5 `total` في مكان و`totalDA` في آخر · تجهيزات كانت `string` لا نوعاً

`kind: 'DOORS'` تُوسَّع إلى `string` في مصفوفة غير مُعلَّمة ⇒ المصفوفة **ليست** `CabinetZone[]` فعلياً، وأي إضافة لاحقة لحقل في `CabinetZone` كانت ستمرّ دون فحص. 26 موضعاً ثُبِّتت أنواعها.
