## 1. المشكلة التي كانت في `test.md`

> «لا يوجد اختبار للواجهة React … الضغط على زر إضافة خزانة، تعطيل زر الإضافة، اختيار الخامة، التعديل، الحذف، Undo، تصدير BOM، طباعة الفاتورة، عرض التحذيرات بالعربية، تحديث المخزون بعد تعديل UI.»

كل هذه البنود صارت مغطّاة — **على التطبيق نفسه**، لا على نسخة مزيّفة: الاختبار يُقلع `App` الحقيقي داخل `FurnitureProvider` الحقيقي، ويضغط الأزرار التي يراها المستخدم، ويكتب في النموذج نفسه.

## 2. لماذا أداة جديدة: Vitest + jsdom

| المحاولة | النتيجة |
|---|---|
| `node:test` + `tsx` (المستخدم للمحرّكات) | ❌ `import.meta.env` غير معرّف ⇒ `App` لا يُستورد أصلاً |
| `react-dom/server` | ❌ لا نقر ولا حالة ولا أحداث |
| Playwright | ❌ يحتاج تنزيل متصفحات وبيئة رسومية |
| **Vitest + jsdom + Testing Library** | ✅ `import.meta.env` حقيقي، DOM كامل، أحداث، وتشغيل في 10 ثوانٍ |

المحرّكات **بقيت** على `node:test` بلا تغيير (سريعة، بلا DOM):

```
npm test        → 248 محرّكاً (tsx --test tests/*.test.ts)
npm run test:ui → 14 واجهة  (vitest run ui-tests/)
npm run test:all → الاثنان
```

`ui-tests/setup.ts` يوفّر ما تفترضه المتصفحات: `ResizeObserver`، `matchMedia`، و`getContext` فارغ (jsdom لا يرسم). **المشهد ثلاثي الأبعاد لا يُختبر** — لا WebGL في jsdom — وهذا مذكور صراحة في التقرير بدل ادّعاء تغطية.

غيّرت نصّ اللافتة في `App.tsx` من «المخزون لا يكفي هذه المطبخ» إلى `BANNER_DISABLED`:

```

```

ثم أُعيد الملف كما كان. الاختبار **يسقط فعلاً** عند كسر الميزة.

## 4. ما كشفته الاختبارات عن التطبيق نفسه

| الملاحظة | التفسير |
|---|---|
| «حقن وتثبيت» معطّل من أول تشغيل | **صحيح ومقصود**: لا خامة ⇒ لا خزانة. وهذا بالضبط بند `test.md` «تعطيل زر الإضافة عند وجود خطأ» — والعطّل هنا **على الخامة لا على الزر** |
| تحذير `manifest.json: Failed to parse URL` | محاولة قراءة ملف نماذج في بيئة الاختبار؛ لا يؤثر على الواجهة |
| رسم 3D لا يُختبر | لا WebGL في jsdom — يحتاج Playwright أو متصفحاً حقيقياً |
| `window.confirm` يُستبدل في الاختبار | الحذف يمرّ بتأكيد المستخدم؛ الاختبار يثبته ويعدّ النداءات |
