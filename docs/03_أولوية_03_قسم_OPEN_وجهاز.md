## 1. النتيجة الأولى: الفرضية في `code.md` و`test.md` **خاطئة**

كان التحليل يقول إن `base.ts` تحذف القاعدة لأي خزانة فيها قسم `OPEN`، مقترحاً استبدال:

```ts
if (isOpenCarcase(zonesOf(cab))) …
```

لكن قراءة `isOpenCarcase` تُظهر أنها **دقيقة أصلاً**:

```ts
export function isOpenCarcase(zones: CabinetZone[]): boolean {
  const a = zones.length === 1 && zones[0].kind === 'APPLIANCE' ? zones[0].appliance : undefined;
  return a !== undefined && OPEN_BAY_APPLIANCES.includes(a);   // DISHWASHER · FRIDGE · WASHER · DRYER · UNDER_FRIDGE
}
```

تشترط **ثلاثة** شروط: قسم واحد فقط · نوعه `APPLIANCE` · والجهاز من قائمة الأجهزة التي تقف على الأرض.
إذن `OPEN` (رفوف مفتوحة) **لا يمكن** أن تُلغي القاعدة.

### الإثبات التجريبي (قبل أي تعديل)

```
OPEN shelves + DOORS + WOOD     → base=WOOD  ignored=-
single OPEN shelves + WOOD      → base=WOOD  ignored=-
DISHWASHER alone + WOOD         → base=NONE  ignored=APPLIANCE_BAY
OVEN alone + LEGS               → base=LEGS  ignored=-
```

وأُضيفت الاختبارات التي طلبها `test.md` حرفياً — **ونجحت من أول تشغيل**:

```ts
test('open shelving keeps its base: an OPEN zone is not an appliance bay', …)
test('built-in appliances keep the base; only the ones that stand on the floor drop it', …)
```

> **درس:** التحليلان بُنيا على قراءة الكود بلا تشغيل، فأخطآ في هذه النقطة. أي توصية تُبنى على قراءة فقط يجب أن تُثبت بتشغيل.

## 2. النتيجة الثانية: عطل حقيقي أضيق في المكان نفسه

أثناء الفحص ظهر هذا السطر في `isOpenCarcase`:

```ts
const a = zones.length === 1 && …
```

الشرط `zones.length === 1` يعني: إذا كان **الجهاز الأرضي في القسم السفلي وله قسم فوقه** (أبواب أو أدراج أو لوح ثابت)، فإن الدالة ترجع `false` ⇒ **تُطبَّق قاعدة تحت الجهاز**.

### الأثر الفيزيائي

| | جسم الخزانة | فتحة الجهاز |
|---|---:|---:|
| قاعدة 100 مم مُطبَّقة | 770 مم | تبدأ من **100 مم** فوق الأرض |
| المفروض | 870 مم | تبدأ من **0** |

أي أن الغسالة تُرفع 10 سم عن الأرض وتُحصَر في فتحة أقصر من مقاسها. غسالة قياسية تحتاج 820 مم، والفتحة المتاحة 770 مم ⇒ **الجهاز لا يدخل**.

### الإصلاح

قاعدة جديدة صريحة في `zones.ts`، وتُستعمل في `base.ts`:

```ts
// zones.ts
export function isApplianceBayAtBottom(zones: CabinetZone[]): boolean {
  const z = zones[0];
  return !!z && z.kind === 'APPLIANCE' && !!z.appliance && OPEN_BAY_APPLIANCES.includes(z.appliance);
}

// base.ts
if (isApplianceBayAtBottom(zonesOf(cab))) return { ...NONE_BASE, ignored: 'APPLIANCE_BAY' };
```

| قبل | بعد |
|---|---|
| `isOpenCarcase` — تتطلب الجهاز **وحيداً** | `isApplianceBayAtBottom` — يكفي أن يكون **في القسم السفلي** |
| رفوف مفتوحة ⇒ قاعدة محفوظة ✅ | رفوف مفتوحة ⇒ قاعدة محفوظة ✅ (لم يتغيّر) |
| غسالة + أبواب فوقها ⇒ قاعدة تُطبَّق ❌ | قاعدة **تُلغى** ✅ |

**لم يتغيّر:** الفرن والميكروويف وآلة القهوة (أجهزة مدمجة في جسم الخزانة) تُبقي قاعدتها — كما ينبغي.

## 3. الاختبار الثالث (أحمر → أخضر)

```ts
test('a floor appliance under another zone still puts the whole unit on the floor', () => {
  for (const base of [{type:'LEGS'…}, {type:'WOOD'…}, {type:'PLINTH'…}]) {
    const cab = make(600, 1000, 600, [
      { kind: 'APPLIANCE', appliance: 'WASHER' },
      { kind: 'DOORS', count: 2, shelves: 0 },
    ], { base });
    assert.equal(baseOf(cab).type, 'NONE');
    assert.equal(baseOf(cab).ignored, 'APPLIANCE_BAY');
    assert.equal(bodyView(cab).height, 1000);      // لا شيء يُخصم من الارتفاع
    assert.equal(geoOf(cab).base.length, 0);       // لا يُرسم شيء تحت الخزانة
    assert.equal(hwQty(cab, 'legs'), 0);           // ولا تُشترى أرجل
  }
});
```

يرفض الإصلاح أنصاف الحلول: يتحقّق من **الارتفاع + الرسم + BOM + المخزون** لا من `baseOf` وحدها.

```
قبل:  not ok 59 → # pass 220 · # fail 1
بعد:  # pass 221 · # fail 0 · tsc ✓ · build ✓
```

## 4. التحقق من السيناريو الواقعي (خزانة طويلة 1338 مم)

غسالة 820 مم + خزانة أبواب فوقها:

```
base = NONE · ignored = APPLIANCE_BAY
bands: APPLIANCE 18..838  /  DOORS 856..1320
issues: APPLIANCE_TOO_NARROW   ← بسبب عرض الخزانة 600 (داخلي 564)، الجهاز يحتاج 596
```

الآن الجهاز يبدأ من الأرض ويأخذ ارتفاعه الصحيح 820 مم، والتطبيق **يرفض** المقاس الضيّق برسالته الصريحة بدل أن يخفيه.
ورسالة الواجهة الموجودة أصلاً صحيحة: «الجهاز يقف على أرجله الخاصة، فلا تُطبَّق قاعدة تحت هذه الخزانة.»

## 5. ما بقي غير مثالي (بصراحة)

| النقطة | التفصيل |
|---|---|
| **لوح القاع لا يزال يُقص** | `isOpenCarcase` (المسؤولة عن حذف لوح القاع والظهر) ما زالت تشترط القسم الوحيد. ففي «غسالة + أبواب فوقها» يُقص **Bottom Deck Panel** عند الأرض ⇒ الجهاز يقف على 18 مم خشب لا على البلاط. |
| لماذا لم أصلحها الآن | إصلاحها يعني جعل حذف الألواح **لكل قسم** لا للخزانة كلها — تغيير في قلب `partsEngine`/`zones` يمسّ ~218 اختباراً. يستحق جولة مستقلة بأمثلتها. |
| الحماية الحالية | التطبيق يطلق `APPLIANCE_ZONE_TOO_SHORT` عند أي محاولة غير ممكنة، ويمنع الإضافة (`blockingIssues`)، فلا يُنتج تصميماً خاطئاً بصمت. |
