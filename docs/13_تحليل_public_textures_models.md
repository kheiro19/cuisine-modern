# 13 — تحليل مجلد `public` المرفوع: هل يؤثر على تحديثات الأولوية 10؟

**التاريخ:** 2026-10-23 · **المصدر:** `public/` داخل مجلد Drive `cuisine-modern-main`
(`textures` = 307 صورة · `models` = ملف واحد).

**الخلاصة في سطر:** لا يُبطل أي إصلاح، ولا يمسّ 264 اختباراً — لكنه **يكشف ثغرة تسليم**:
الحزمة التي سلّمتك إياها تحتوي الكود بـ`textureManifest` من 307 أسماء **بلا الصور نفسها**،
و`prebuild` على Vercel يحوّل ذلك المانيفست إلى `[]`. أي أن النشر من الـZIP وحده = تطبيق **بلا خامات**.

---

## 1. ما رُفع فعلياً (مقيس، لا مفترض)

| العنصر | العدد | الملاحظة |
|---|---|---|
| `public/textures/*.webp` | **307** | كلها `.webp` بلا استثناء |
| الحجم الكلي | **6,855,134 بايت = 6.54 MB** | الوسيط 19,810 B · الأكبر 87,114 B |
| ملفات 56 بايت | **64** | ألوان مسطّحة، سليمة (انظر §5) |
| أكواد ديكور متمايزة | **167** | + 140 نسخة `_002` |
| `public/models/` | **1** | `library/manifest.json` فقط · **لا يوجد أي `.glb`** |

## 2. المقارنة الحاسمة: أسماء Drive ↔ `src/data/textureManifest.json`

```
ملفات Drive      : 307
سطور المانيفست   : 307 (بلا تكرار)
في Drive وليس في المانيفست : 0      ← لا ملف يتيم
في المانيفست وليس في Drive : 0      ← لا صورة 404
المجموعتان متطابقتان       : نعم ✔
```

هذه أهم نتيجة في التحليل: **التطابق تام**. لا انزياح تسمية، ولا نسخة قديمة/جديدة.
لذلك نسخُ المجلد كما هو يُعيد الحالة التي يصفها المانيفست بالضبط — **صفر تغيير في الكود**.

## 3. الثغرة: ماذا يحدث فعلاً عند `npm run build` بدون `public/textures`

`package.json` يشغّل `prebuild` → `scripts/build-texture-manifest.mjs`، وهذا السكربت
**يكتب فوق** المانيفست بما يجده على القرص. جرّبته على نسخة مفكوكة من الـZIP الذي سلّمتك:

```
manifest BEFORE (المشمول في الـZIP) : 307 entries
$ node scripts/build-texture-manifest.mjs
[textures] /tmp/ziptest/public/textures not found - writing an empty manifest
[textures] 0 valid image(s) listed
manifest AFTER                      : 0 entries
```

ثم بعد وضع مجلد `textures` (بصورتين تجريبيتين):

```
[textures] 2 valid image(s) listed
manifest: ["FL-E098_sZUy.webp","tile_sZUy.webp"]
```

**الأثر على النشر:**

| السيناريو | ما يراه المستخدم |
|---|---|
| الـZIP وحده → Vercel | تبويب «Workshop Matrix (**0**)» — لا خامة واحدة، لا حتى صورة مكسورة |
| الـZIP فوق مشروعك الحالي (معه `public/textures`) | 307 خامة، كل شيء سليم |
| تفتح المشروع محلياً بـ`npm run dev` | نفس القاعدة: `predev` يمحو المانيفست إن غاب المجلد |

هذا يفسّر أيضاً الحادثة الموثّقة سابقاً («المانيفست صار `[]`») — كانت **غياب المجلد**، لا خطأ في السكربت.

## 4. مجلد `models`: لا شيء يُنتظر منه

- Drive يحتوي `library/manifest.json` فقط، وحجمه **114 بايت**.
- محتواه:
  ```json
  { "version": 1, "generatedAt": "2026-10-23T10:23:06.847Z", "files": {}, "library": {}, "warnings": [] }
  ```
- وهو **مطابق حرفياً** للنسخة الموجودة في الـZIP (نفس `generatedAt`، نفس البايتات 114).
- لا `.glb`، لا `.gltf`، لا `library.json`.

**الحكم:** صفر أثر. هو مجرد ملف فارغ يولّده `npm run models` عند كل `dev`/`build`.
رفعه لا يضيف نموذجاً ولا يكسر شيئاً. أي نماذج 3D حقيقية ما زالت غير موجودة في المشروع.

## 5. الملفات ذات 56 بايت: ليست تالفة

حمّلت واحدة من Drive وفحصت ترويسة البايتات:

```
FL-E098_sZUy.webp  56 bytes  RIFF/WEBP — VP8X 512×512
tile_sZUy.webp    904 bytes  RIFF/WEBP — VP8X 512×512
```

الـ56 بايت هي لون واحد مسطّح بحجم 512×512 (ضغط WebP المثالي لهذه الحالة ≈ 56 بايت).
وسكربت المانيفست **لا يعتمد على الحجم** بل على الترويسة:
`RIFF` + `WEBP`، ويرفض ما لا يطابقها. لذلك الـ64 ملفاً مسجّلة كلها كصور صالحة — وهي كذلك.

## 6. العيب الحقيقي الذي كشفه الرفع (ليس من الـZIP، بل قائم قبله)

`src/math/textureEngine.ts` يبحث عن الخامة آلياً بهذه القاعدة:

```ts
const prefix    = isWood ? 'wood_' : 'stone_';
const cleanBrand = material.brand.toLowerCase().replace(/[^a-z0-9]/g, '');  // "EGGER (Austria)" → "eggeraustralia"
texturePath = resolveConventionTexture(prefix, cleanBrand);                   // wood_eggeraustralia.webp
```

بينما الأسماء الحقيقية:

```
FL-S401_sZUy.webp · FL-W606_sZUy.webp · tile_sZUy.webp · grain-1x1x750x750_sZUy.webp …
```

**لا يوجد ملف واحد يبدأ بـ`wood_` أو `stone_`.** النتيجة:

- **0 من 307** خامة تُطابَق آلياً بعلامة/كود المادة.
- ما يعمل فعلاً هو الاختيار اليدوي: `frontTextureOverride.path` من تبويب «Workshop Matrix (307)».
- العلامات في المشروع نصية (`"EGGER (Austria)"`, `"AGT (Turkey)"`) والكود `FL-…` لا يظهر في أي ملف `src`.

هذا **سلوك سابق للرفع وليس ناتجاً عنه**، لكن الرفع يجعله مرئياً: أصبح المخزون حقيقياً،
وبات الفارق بين «307 خامة تختارها بيدك» و«خامة تُسند تلقائياً حين تختار EGGER S401» واضحاً.

## 7. ما يتغيّر في ملفات المشروع؟

**لا شيء.** لا تعديل مصدر، لا اختبار، لا إعداد. البوابات تبقى كما هي:

```
npm test          264 / 264
npm run test:ui    39 / 39
typecheck           ✓
build               ✓
```

التغيير الوحيد **في طريقة التسليم**: الـZIP ليس مشروعاً مستقلاً — هو طبقة كود
تُفكّ فوق مشروعك الذي يملك `public/textures` أصلاً.

| الملف | في الـZIP؟ | في Drive؟ |
|---|---|---|
| `src/`, `tests/`, `docs/`, `scripts/` | ✔ | ✔ (نسخة أقدم) |
| `public/models/library/manifest.json` | ✔ | ✔ (مطابق) |
| `public/textures/` (307 · 6.54 MB) | ✘ | ✔ |

## 8. الخيارات التالية (لم يُنفَّذ منها شيء — تنتظر قرارك)

1. **الدمج البسيط (موصى به):** فكّ الـZIP فوق مشروعك، واترك `public/textures` كما هو. صفر كود.
2. **حارس بناء:** إن كان عدد الخامات 0 وقت `prebuild` → يُفشل البناء برسالة عربية واضحة
   بدل نشر تطبيق فارغ. سطران في `build-texture-manifest.mjs` + اختبار.
3. **إسناد آلي بالكود:** توسيع `resolveConventionTexture` لتجرّب أيضاً `FL-<code>_sZUy.webp`
   (و`_002`)، فيصبح كود الخامة في المخزون كافياً لظهور وجهها الحقيقي. يحتاج قراراً في
   تعريف `brand` مقابل `code` في `src/types/flatma.ts`.

## 9. ملاحظة على مجلد Drive

`public/` في Drive لا يظهر داخل الـZIP، ولا يمكن أن يمثّل «حذفاً» لأي ملف
(وهو ما فعلته الأولوية 10). لذلك: **الـZIP = الكود · مجلد `public` = الأصول**.
