## 1. ما كان ناقصاً بالضبط

الاختبارات القديمة كانت تفحص `applyConsumptionDelta` **منفردة**:

```ts
const added = S.applyConsumptionDelta(stock, [], [cab]);   // ✓ يشتغل
const back  = S.applyConsumptionDelta(added, [cab], []);  // ✓ يرجع
```

لكن هذا لا يثبت أن **التطبيق** يستعملها. لو حُذف سطر واحد من `FurnitureContext.commit()` لكان كل اختبار محرّك **ما زال أخضر** والمخزون في التطبيق لا يتحرّك أبداً.

> الفرق بين «الدالة صحيحة» و«الدالة **موصولة**».

## 4. إثبات أن الاختبار حقيقي (mutation)

حذفت سطر المخزون من `commit()`:

```diff
- commitInventory({ ...inv, hardwareItems: applyConsumptionDelta(inv.hardwareItems, before, next) });
+ commitInventory({ ...inv });   // MUTATION
```

النتيجة:

```
Tests  7 failed | 2 passed (9)     ← اختبارات الواجهة تسقط
```

ثم أُعيد السطر (`grep -c applyConsumptionDelta` = 2). **الاختبار يحمي التوصيل فعلاً**، وليس مجرد حساب صحيح في دالة معزولة.

> الاختباران اللذان نجحا أثناء الطفرة هما «نقطة الأساس» و«العجز» — لأنهما لا يعتمدان على الخصم. وهذا سلوك متوقّع وموثّق.

## 5. ما لم يُثبت (بصراحة)

| البند | الحالة |
|---|---|
| خصم **الألواح** عند الإضافة | ❌ لا يحدث — قرار موثّق في `docs/06`: القراءة من نقطة الأساس، لا خصم فعلي |
| خصم **أمتار الحواف** | ❌ نفس السبب |
| حدّ 20 خطوة في سجل التراجع | غير مغطّى (السلوك موجود: `if (updatedStack.length > 20) shift()`) |
| Undo بعد إضافة **مخزون** | لا يُلغي إضافة المخزون (مقصود: المخزون ليس جزءاً من المشروع) |
