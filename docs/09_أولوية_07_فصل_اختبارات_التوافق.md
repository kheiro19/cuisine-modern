## 3. الحل الهندسي: `corpus.ts` بدل الاستيراد المباشر

المشكلة الدقيقة: `engines.test.ts` يختبر **وعداً في المنتج** (السعر يساوي مجموع صفوف BOM) لكنه يمرّنه على **أشكال قديمة**. هو ليس اختبار توافق، لكنه كان يستورد بيانات الكتالوج.

```ts
// قبل — اقتران بالبيانات المهملة
import * as LG from '../fixtures/legacy';
const d = LG.draftFromPreset('Deep_Drawers');

// بعد — اسم صادق: مجموعة أشكال للتجربة
import * as C from '../fixtures/corpus';
const d = C.draft('Deep_Drawers');
```

`corpus.ts` (32 سطراً) يعطي **اسماً محايداً**: «أشكال للتجربة». الفرق ليس تجميلاً:

> لو حُذف الكتالوج القديم، **يسقط ملف واحد** (`corpus.ts`) ولا تُلمس حزمة المنتج — لأن المنتج لا يعرف أن أشكاله «قديمة».

## 5. ملاحظة صراحة: اختبار حُذف ثم أُعيد

أثناء التقسيم سحبت كتلة من `rules.test.ts` (عائلة القوالب + تعريفاتها)، ومعها — بالخطأ — اختبار **منتج**:

```
kinematics: a MODELLED mechanism has stock category + quantity rule
```

كشفته مقارنة أسماء الاختبارات قبل/بعد:

```bash
grep -ho "test('[^']*'" /tmp/tests.bak/*.test.ts | sort > old.txt
cat tests/*.test.ts tests/product/*.test.ts tests/compat/*.test.ts | grep -ho "test('[^']*'" | sort > new.txt
diff old.txt new.txt
```

النتيجة النهائية للفرق: **صفر اختبار مفقود**؛ كل ما ظهر هو 5 اختبارات الحارس + إعادة صياغة اختبار واحد (بقيت دلالته).

> الدرس: **نقل الاختبارات عملية خطرة مثل تعديل الكود** — تستحق نفس المقارنة قبل/بعد.
